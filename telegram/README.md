# Телеграм-бот: задачи агенту с телефона

Бот принимает сообщения в Telegram и отдаёт их Claude Code, запущенному
в папке проекта `Ber&Bar` на этом компьютере. Ответ агента приходит в чат.
Контекст разговора сохраняется: следующее сообщение продолжает предыдущее.

Зависимостей нет — только Node (стоит 24-й) и `claude` в PATH.

## Настройка, один раз

1. В Telegram открыть **@BotFather** → `/newbot` → придумать имя и логин.
   BotFather выдаст токен вида `1234567890:AAH...`.
2. Скопировать `telegram/.env.example` в `telegram/.env`, вставить токен
   в `TG_BOT_TOKEN`.
3. Запустить бота: двойной клик по `telegram/start-bot.cmd`
   (или `npm run bot` в папке проекта).
4. Написать боту в Telegram любое сообщение — он ответит вашим `chat id`.
   Вписать этот id в `.env` в `TG_ALLOWED_IDS` и перезапустить бота.
   Пока список пуст, бот никого не слушает — это защита от чужих.

Всё, дальше просто пишете задачи в чат.

## Команды

| команда | что делает |
|---|---|
| обычный текст | задача агенту в папке проекта |
| `/razrab` | новый разговор с промптом разработчика сезонности |
| `/auditor` | новый разговор с промптом аудитора |
| `/tester` | новый разговор с промптом тестировщика |
| `/novaya` | забыть прошлый разговор |
| `/stop` | прервать то, что выполняется, и очистить очередь |
| `/status` | папка, сессия, режим прав, очередь |
| `/papka <путь>` | сменить рабочую папку (по умолчанию `Ber&Bar`) |
| `/rezhim <режим>` | права агента на действия |
| `/id` | показать свой chat id |

К роли можно сразу приписать задачу: `/razrab добавь снегопад на главную БП`.

Пока задача выполняется, бот правит одно сообщение: сколько секунд идёт,
сколько шагов сделано и чем занят сейчас (какой инструмент, какой файл).
Новые сообщения в это время становятся в очередь — задачи идут по одной.

Слэш-команды самого Claude Code (`/code-review`, `/security-review` и другие)
бот не перехватывает, а передаёт агенту как есть.

## Права агента

Режим ставится в `.env` (`CLAUDE_PERMISSION_MODE`) или на ходу командой
`/rezhim`:

- `plan` — только планирует, ничего не меняет;
- `acceptEdits` — правит файлы сам, но команды в терминале выполнить не может
  (в неинтерактивном режиме спросить разрешение не у кого, и они отклоняются);
- `bypassPermissions` — делает всё без вопросов. Нужен, если задачи требуют
  git, npm, скриптов из `tools/` или MCP. Это ваш осознанный выбор: бот
  работает на вашей машине от вашего имени, поэтому доступ к боту должен
  быть только у вас (`TG_ALLOWED_IDS`).

По умолчанию стоит `acceptEdits`.

## Файлы и фото

Присланные в чат фото и документы бот кладёт в `telegram/vhod/` и добавляет
путь к тексту задачи — агент видит файл на диске. Голосовые и видео пока
не разбираются.

## Служебное

- `telegram/state.json` — id сессии по каждому чату, рабочая папка, режим,
  позиция в очереди обновлений Telegram. В git не идёт.
- `telegram/log/bot.log` — когда запускался, сколько шла задача, ошибки.
- Бот использует long polling: никакие порты открывать и пробрасывать
  не нужно, наружу компьютер не выставляется.
- Обрыв связи с Telegram бот переживает: запросы повторяются четыре раза
  с нарастающей паузой, одиночный сбой пишется в лог и не гасит процесс.
  Если процесс всё же упадёт, `start-bot.cmd` поднимет его через 5 секунд.
- Запустить без окна на экране:
  `powershell -Command "Start-Process cmd -ArgumentList '/c','telegram\start-bot.cmd' -WorkingDirectory '<папка проекта>' -WindowStyle Hidden"`.
  Остановить — `telegram/stop-bot.cmd`.
- Пока компьютер спит или окно закрыто, бот не отвечает. Сообщения
  не теряются — Telegram хранит их и отдаёт при следующем запуске.
- Автозапуск со входом в Windows: `Win+R` → `shell:startup` → положить туда
  ярлык на `start-bot.cmd`.
