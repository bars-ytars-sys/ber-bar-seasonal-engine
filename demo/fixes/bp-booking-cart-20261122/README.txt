БП, /booking — защита корзины, 22 ноября 2026.

Причина: дочерний Bnovo получает rev-manifest.json асинхронно, но init_cart
может отправиться раньше. Внешняя корзина вызывает this.manifest['css/main.css']
до готовности manifest. После подтверждения initialized родная корзина уже
спрятана, а внешняя не отрисовывается.

Защита ставится только на экземпляр BnovoBookFrame страницы БП перед init().
Если manifest ещё нет, внешний компонент не создаётся и не подтверждается:
остаётся стандартная корзина Bnovo. Тарифы, даты, дом, гости, шаги оформления
и отправка бронирования остаются в родном Bnovo. Файлы провайдера не меняются.

Если внешняя корзина уже успешно загружалась в текущем окне, её manifest
сохраняется до конца этой сессии: неполное следующее сообщение не обнулит CSS.
Состояние корзины и услуги не кешируются и не подменяются.

Глобальный BookingIframe.prototype, шапка, HEAD, SEO и формы не изменяются.
Для переноса необходима сверка с точной текущей копией T123 rec850832895.

Воспроизводимая проверка (требуются Playwright и WebKit):
1. release.py OUT --booking editor-booking.html --houses editor-houses.html
   --raw-booking published-booking.html --raw-houses published-houses.html
2. node demo/fixes/bp-booking-cart-20261122/race-check.mjs OUT
Проверка использует реальный Bnovo, задерживает только первый manifest10сек,
блокирует все запросы записи и останавливается на форме гостя. Исходный
вариант должен воспроизвести ошибку; исправленный — пройти путь без неё.
Скриншоты и JSON остаются в OUT; их не коммитить с данными гостя.
